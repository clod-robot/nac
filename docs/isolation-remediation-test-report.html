五、缺陷与风险

D-01（严重 · 环境）Novawaf WAF 将「请求体含私网地址」判定为攻击，误拦隔离/修复相关接口
  • 管理端保存隔离配置：body 含 remediationPortalUrl=http://192.168.100.2:8080/remediation → HTTP 403；同一请求去掉该字段 → HTTP 200。
  • 客户端软件基线上报：body 含 "ip":"10.0.0.66" → HTTP 403；不含私网 IP → 通过。经 WAF 的客户端上报链路不可用。
  • 触发条件已收敛：http://私网IP:端口、http://私网IP/路径、10.0.0.66 均触发；http://a.b/c 不触发。
  • 修复建议：在 Novawaf 控制台为 NAC 增加路径级「放行(pass)」策略（/api/client/、/api/auth/admin/isolation/），或对该站点关闭私网地址检测规则。本次已通过控制台 API 添加 pass 策略（appId=1 与全局两种作用域）验证，当前引擎版本下均未绕过拦截，已全部回删，需按引擎版本核实策略生效条件（应用识别/热加载）。
D-02（中 · 环境）WAF 限流触发 429，影响管理端连续页面加载
  • 现象：连续打开管理端页面时返回 429 Too Many Requests 错误页，间隔约 60 秒后恢复。
  • 影响：管理端首次巡检时可能短暂无法打开页面；不影响接口幂等与数据一致性。
  • 建议：核对 WAF 的 CC 防护阈值与静态资源白名单，将 /nac/assets/ 排除在限流之外。
D-03（低 · 设计确认）弹窗与缺失项使用「策略显示名」
  • 实测：策略名为 QA-QQ、进程名为 qq.exe 时，missing 与弹窗正文展示 QA-QQ。
  • 建议：若策略名允许与真实软件名不一致，可为策略增加「显示名称」字段，避免终端用户看到内部编号。

六、结论

功能结论：通过。 除 J1（WAF 误拦，属环境配置问题）外，30 个用例中 29 个通过，覆盖实时/ONCE 两种校验模式、全局与策略级弹窗、ACL 与 VLAN 双通道隔离下发、隔离区与修复区流转、补丁与病毒库联动、修复任务下发与上报、合规后自动释放。

待办：修复 Novawaf WAF 私网地址误判（D-01）后复测 J1，并验证真实终端经 WAF 上报软件基线的完整链路；同时按 D-02 调整限流策略。
